# 序列号仓（实现说明）

本仓把 `docs/资料口径.md` 的来源语义落成可装载、可查询的 DuckDB 仓，
不改变资料本身，也不替代器械审批。全部数据为合成数据，不含患者信息。

## 分层

| 层 | 表 | 作用 |
| --- | --- | --- |
| 接收 | `meta_session` / `meta_receive` / `meta_source_pack` | 每次装载生成会话，记录文件摘要、接收次序与接收时刻 |
| 前区 | `landing_*` | 只追加的原始行，保留每次接收的版本 |
| 金区 | `current_*` / `fact_*` / `rule_period` | 去重后的现行主数据、随时间变化的装配/位置/质量事实 |
| 集市 | `mart_*` | 当前可用、位置快照、待核冲突、冻结的对账修订 |

`fact_*` 与 `rule_period` 都带 `session_id`：每个会话物化自己“当时已知”的事实，
所以后来的修订不会改写已确认的历史解释。

## 时间口径

- 业务时刻保存为 +08:00 的业务本地时间（仓内为 TIMESTAMP）；接收时刻另存于
  `meta_receive.decided_at`，两者不混用。
- 所有区间左闭右开 `[start, end)`；`end` 为空表示仍在生效。
- 历史查询 `as_of` 只使用该时点之前已知的扫描、质量事件与装配区间。
- 组成规则的版本：规则首次接收时从资料最早业务时刻起生效；之后的新版本从
  接收时刻起生效。历史截点因此仍看到旧组成，新查询才看到新组成。
- 缺回库扫描的件按“在途或未知”处理，不写成已返回。

## 业务规则落点

| 口径 | 实现 |
| --- | --- |
| 整套发运单 + 同单部件扫描 = 一次交付 | `fact_delivery`（销量）+ `fact_delivery_scan`（证据） |
| 一套不等于很多台 | `delivered_sets` 只数 `kind=sale` 的 shipment 行 |
| 借件恢复服务但不增加销量 | `basis=loan` 计入在套件与可用性，不计 `delivered_sets` |
| 服务中断 | 必需件数量不足或必需件 `nonworking`；`interruption_intervals` 给出区间 |
| 换件闭合 | 原件离场 + 新件到场 + 原件回库三件齐全；否则 `open` |
| 批次追查 | `lot_affected` 只报查询时点实际在套的件，历史件单列且标注不代表当前 |
| 同号冲突 | 只有同一厂商内同 serial 多键才进入 `serial_collision` 复核 |
| 重叠装配 | 同一件同一时刻装在两套 → `overlap_assembly` 复核 |

## 命令行

```bash
python3 -m pip install -r requirements.txt

# 装载（首次可用任意路径；同摘要文件不会生成新会话）
python3 -m sourcepack load --db build/wh.duckdb --root . --label 初始资料

# 商务：客户已交付 / 当前可用
python3 -m sourcepack availability --db build/wh.duckdb --customer C1

# 仓储：序列号 → 整套；整套 → 当时在客户处的各件
python3 -m sourcepack component --db build/wh.duckdb --key A:2
python3 -m sourcepack kit --db build/wh.duckdb --kit A:K1 --as-of 2026-10-15T00:00:00+08:00

# 批次追查（当前受影响 vs 仅历史）
python3 -m sourcepack lot --db build/wh.duckdb --lot L2

# 售后责任：中断经历、未闭合换件、借件
python3 -m sourcepack service --db build/wh.duckdb --customer C1

# 冻结对账并比较补正前后
python3 -m sourcepack reconcile --db build/wh.duckdb --customer C1 --note 首次对账
python3 -m sourcepack revisions --db build/wh.duckdb --customer C1
python3 -m sourcepack compare --db build/wh.duckdb --left 1 --right 2

# 待核范围与会话列表
python3 -m sourcepack conflicts --db build/wh.duckdb --session session-0001
python3 -m sourcepack sessions --db build/wh.duckdb
```

所有查询命令支持 `--session`（使用某个历史会话的事实版本）与 `--as-of`
（业务时点）；`availability` / `service` / `reconcile` 由 `--customer` 限定客户。

## 输入约定

- 资料文件按 `data/catalog.json` 的字段、类型与记录键核对；行数或摘要不符即拒收。
- 同一来源记录键的新文件是整行修订，不是新增事实；删除某行不等于删除事实。
- 引用不存在、枚举取值未知、装配结束不晚于开始、互斥组数量无效都会拒收，
  并且失败装载不留下半成品会话。
- 相同文件摘要不增加事实；整份资料无新摘要时不生成新会话。

## 尚未覆盖

- 这不处理计费/结算金额，也不做器械审批或临床判断。
- `contact`、`service_order` 等来源未在现有资料中出现，未建模。
